# Local Master Inspection Plan

This is a **testing build**. Do not rely on it as the only copy of an inspection plan until the launch and data workflows have been verified on your computer. Keep the original workbook and independent backups.

The [2 November full app review](docs/app-review-2026-11-02.md) found nine open defects, including an unrelated save clearing an independent inspection concern and changing snapshot eligibility. Passing automated tests do not close those findings. See the [prioritized repair plan](docs/superpowers/plans/2026-11-02-app-review-fixes.md) before relying on this candidate's cleanup, recovery, interchange and reviewed-update workflows.

Use the **Light mode / Dark mode** control in the header to switch themes from any screen. The choice is remembered in this browser; **Data & backups → Appearance** also lets you follow the system preference.

## macOS

Extract the complete folder somewhere writable. Double-click `Start Inspection App.command`. The app uses its own Python and opens a browser on the local computer. Leave its terminal window open while using the app; close it to stop the app. If macOS blocks the downloaded file, use your organization's approved application procedure.

On first use, open **Data & backups**, choose `reference/Master_Inspection_Plan_Cleaned_Draft.xlsx`, preview the counts, then import. The application stores its database and backups under `data/`. Keep that folder when updating app files. The app is local to this computer and does not share changes with other people.

## Windows

Extract the complete folder to a writable location and double-click `Start Inspection App.bat`. If its local runtime is missing, the launcher downloads the official Python 3.14.10 64-bit embeddable ZIP, verifies its SHA-256 checksum, and places Python plus the app's verified spreadsheet wheels inside the app folder. It does not run a Python installer, change the system Python, or require administrator rights. First setup needs network access to python.org and files.pythonhosted.org; later starts reuse the local runtime, and prebuilt Windows ZIP packages can start offline. Import the workbook in `reference/` on first use. Use Edge, Chrome, or Firefox; Internet Explorer is not supported. Native Windows execution still needs verification.

If you already have a database from an earlier version, **keep your existing `data/` folder**. Replace only the application files and runtime; do not overwrite that folder. Make a separate backup before updating.

To update from the Windows ZIP: close the app, extract the ZIP to a new writable folder, then copy your existing `data/` folder into it. Start the app from the new folder. The ZIP contains no database or backups.

The Windows package also includes the Python regression tests. From Command Prompt in the extracted app folder, run:

```bat
runtime\windows\python.exe -X utf8 -m unittest discover -s tests -v
```

These tests use temporary databases and do not alter your `data/` folder.

## Backups and imports

The Data & backups page accepts the original multi-sheet Master Inspection Plan as well as cleaned workbooks and app exports. After selecting an original workbook, choose which tabs to include using the checkboxes (or Select all / Deselect all), then click **Preview import**. Changing the file or tab selection clears the previous preview. Excluded tabs contribute no imported data, and partial imports use merge so existing records from excluded tabs remain.

Asset extraction supports the original layouts for Vessels & TKs, OP Piping, GP Piping, Turbines Piping, WD-33 Piping, EPFs, MFDs, TLs, FLs, and GL Lines. Other recognized original tabs, including Coolers and Dead Legs, are retained as reference cell data only; the checklist labels their role. Unsupported included tabs or shifted headers must be corrected or excluded. Cleaned workbooks import all seven linked tables together.

Original cell values, formula text with available cached values, and comments are preserved as source evidence. Workbook appearance, images and embedded objects are not imported. Missing or ambiguous inspection months and dates in the wrong order are flagged for review without inventing corrections. Keep the original file independently. The preview compares the last imported source, current master and incoming values. Verified master corrections are retained and incoming differences become review issues. Incoming blanks and missing linked evidence do not silently erase populated master data. Inspect all proposed differences before applying.

If the preview finds duplicate identities or conflicting matches, use **Resolve duplicate and matching conflicts** inside the app. Each affected incoming row shows its original details and any possible existing matches. Choose **Import as a separate asset**, **Skip this incoming row**, or the specific **Update existing** record, then click **Update preview**. To keep one repeated row, select its appropriate separate/existing action and skip the other row. The app does not combine conflicting dates or notes automatically. Skipping never deletes an existing asset, preserves the incoming source cells as skipped evidence, and requires merge mode. All identity conflicts must be resolved before Import becomes available.

Decisions are saved only when the import succeeds. They are reused for unchanged source rows while the existing target remains compatible; changed or moved rows require review again. Full exports preserve saved decisions in an optional **Import Decisions** sheet. Older cleaned workbooks without this sheet remain supported. Choosing a new file or changing selected tabs clears un-applied decisions; nothing is written to the source Excel file.

Automatic local backups run before the first edit each day and before imports, bulk corrections, consolidation, clear and restore. They are kept in `data/backups/`. New automatic database backups use `.db.gz`: each complete copy is compacted and gzip-compressed without deleting records, verification evidence, snapshots or history. Compaction runs on the backup copy, never the live database. Existing `.db` backups remain listed and restorable alongside compressed backups; uploaded backups are detected by their contents. Damaged compressed backups are rejected before replacement. Compressed database restores have a 1 GiB expanded-size limit; larger generated database copies stay in compact `.db` format so they remain restorable. Existing backup files are not converted or removed. In **Data & backups → Saved backups**, select individual backups (or Select all) and choose **Delete selected backups** to remove obsolete local restore points; the confirmation names the files. This does not delete recovery packages, snapshots, source archives, or the active database. The launcher initially configures `data/recovery-copies/` for automatic recovery-package copies, unless you have already chosen another folder. Change the destination and test it under **Data & backups**. Copies on this computer do not protect against loss of the computer; use another drive for that. Failed copies produce a visible warning while preserving the last completed copy. To restore, use the saved-backup selector or upload a full recovery package. A safety backup is created before replacement.

The active database now uses schema 11 and lossless zlib compression for large import payloads, correction-history records, source baselines and retained import references. Original JSON bytes, identities and history are preserved; asset records and workbook formats stay unchanged. Older plain-JSON databases and backups remain supported and are migrated with a safety backup. Compressed databases and new backups require this updated app; older app versions reject schema 11. Corrupt compressed payloads are rejected during backup/recovery validation. Startup compression can free reusable SQLite pages without immediately shrinking the file; explicit offline maintenance compacts a verified candidate and retains an independent original.

An Excel interchange export is available under Data & backups. Full recovery packages contain a compacted database and preserve the verification journal, snapshots and archived original files; use those for complete recovery. Import matches permanent asset IDs: the preview shows proposed updates and records retained, and apply creates a backup. An exported workbook can be imported into an empty database. Different assets are not merged by name. CSV export is available on the asset register.

## Clear or delete stored data

**Imported source coverage** lists populated rows that were not converted into assets and tabs excluded from an import. Expand an entry and choose **Dismiss coverage entry** to remove it from the attention list without losing its evidence. Enable **Show dismissed coverage entries** to restore it.

Under **Data & backups → Manage stored data**, choose a category, select individual records or Select all, and choose **Preview selected deletion**. The preview names the records, source dependencies and exact managed files affected. Type its displayed confirmation to proceed; Cancel changes nothing. Categories cover assets, imported reference data, staged imports, import evidence, original archived workbooks, snapshots, verification evidence, correction/bulk/issue history, recovery ZIP copies and this browser's drafts/reconciliation state. Selected assets also have a delete action in the register; staged imports and snapshots have their own shortcuts.

**Clear asset register** removes assets and imported reference values while retaining coverage, source archives, snapshots and history. **Reset working data** removes the entire working dataset and current-browser drafts. It keeps saved database backups, recovery ZIPs, backup-folder configuration and appearance separately managed. A reset requires typing `RESET WORKING DATA`. Other open pages must reload before making changes.

Data removal creates a database backup and recovery ZIP first; if recovery protection cannot be created, deletion stops. If a copied dataset already has missing or damaged archives, the cleanup preview identifies those gaps. Its protection ZIP preserves the database and every available source byte, explicitly records unavailable originals, and maps damaged or misnamed files to their actual content hashes. It cannot recreate already-missing files. Normal recovery-package downloads remain strict about unexpectedly missing archives. A shared archived workbook is retained when another import still uses it. Deleting evidence while retaining assets keeps minimal source links so missing-source warnings remain visible under the current quality rules. Copies embedded in assets, other history, snapshots or saved backups are not erased by deleting just an import entry. Full reset removes all working copies; previously saved backups remain available. Files downloaded elsewhere and other browsers' local storage are outside the app's deletion scope.

Database backups (including migration backups) are deleted through **Saved backups**. Recovery ZIPs are deleted separately through the **Recovery ZIP copies** category, limited to app-named regular files in the default/configured copy folders. Deleting backup files does not create more backups of them. Changes to database records and managed files roll back together on failure; interrupted file cleanup is recovered at the next app start. Power-loss durability has not been independently verified.

## Clean, verify and maintain

1. Import an original supported workbook or app export. Choose source tabs, inspect extraction coverage, resolve identities and compare proposed changes. Unclassified populated rows require an explicit coverage acknowledgement. The source file is archived unchanged by its content hash. A staged preview can be resumed after restart if the master has not changed. After import, **Imported source coverage** in Data & backups reopens each recent import's unclassified sheet rows and exact archived workbook for follow-up.
2. Use **Data quality** to find current blockers, nonblocking warnings and entries that passed checks automatically. Correct an asset in the editor; source cells remain available on the Source tab. Browser drafts can be recovered only against the same saved asset version.
3. Manual verification is optional and separate from automatic eligibility. For an individual asset, open **Review verification**, check only fields you reviewed, and record evidence or engineering rationale. To verify many records efficiently, select them in the master register across pages and choose **Verify selected**. Review the complete preview of source rows, core field values and blockers, cite the workbook/report, confirm the full selected scope, and apply once. The app still records verification per asset and field. Import alone never verifies anything; blocked assets remain outside trusted snapshots until their blockers are resolved. Saving a correction alone never verifies it. Changed fields lose current verification; unchanged fields retain it, and historical evidence remains visible.
4. An applicable inspection passes schedule checks with a valid next month (including overdue months) or a recorded scheduling condition; a review-by month is optional and never creates a missing-date or overdue-review flag. A blank or Never last date and a missing location do not block automatic eligibility. Missing names/families/applicability, ambiguous dates, next-before-last chronology, shared identifiers and incompatible internal inspections need checking. Historical import date flags are preserved as evidence but current criteria decide eligibility. Missing archived source files warn without excluding an otherwise passing entry.
5. Publish a named trusted snapshot. It automatically includes entries with no open blockers, requires no manual verification, and lists **every excluded asset and reason**, along with warnings, exceptions, rule version and source batches. Later edits do not rewrite historical snapshots.
6. For repeated corrections, select assets across register pages, preview all bulk changes and record a reason before applying. Reverting is a new correction and is refused if any affected asset has subsequently changed. Duplicate consolidation requires exactly two selected records, an explicit survivor and a decision for every conflict. Retired IDs remain aliases; evidence and history are preserved.

The register and quality worklist use server pagination; source-cell and technical evidence is loaded with the editor. Exporting filtered or selected records still covers the complete selected scope, rather than only the visible page. Yearly exports include scope and omitted-inspection reasons. Oversized Excel strings are stored in indexed continuation rows and reassembled on import.

Reviewer attribution is a local owner label and evidence record, not authenticated approval. This app maintains a master register and schedule; verification does not certify equipment safety or regulatory compliance.

## Known testing limits

The automated tests exercise workbook import, reconciliation, edits, export/re-import, backups, restore, month logic, local HTTP requests, Unicode paths, and cross-process data locking. The Python suite is checked on Python 3.11 and 3.14 on macOS. Windows encoding and isolated import-path failures have regression coverage. The new quality/verification workflow has been exercised in the macOS in-app browser using disposable synthetic data. Native Windows execution, a complete screen-reader/contrast audit and owner acceptance on the intended original workbook remain release gates. The app does not implement shared team access.

Choose the independent backup destination with **Browse…** in Data management → Automatic backup copies. The native Windows/macOS folder chooser saves the selected folder; cancelling keeps the previous destination.

In **Data quality → Year-only inspection dates → Review year-only dates**, preview adding January to retained four-digit years for both last and next inspection dates. Review the year groups and remaining issues, then apply with a recorded reason. Existing months, blanks and other ambiguous values stay unchanged. **Revert last bulk correction** can undo it if those records have not subsequently changed.

The November 2026 review repairs have synthetic regression and disposable browser coverage, including reset followed by yearly Excel export. Native Windows, packaged macOS, owner workflow and full accessibility acceptance remain outstanding; see [the review](docs/app-review-2026-11-02.md).

## Editable Excel database and annual reports

Use **Export to Excel** in the master register, or **Data & backups → Export to Excel**. The **Full Database Workbook** follows the original source-tab layout: each asset and its inspection, technical, note and review fields share one row on that asset's source tab. It supports field-level conflict resolution and validated business-data recovery. Choose **Yearly Inspection Plan** for a separate report with an independent planning year, filters, monthly totals, charts and optional January–December sheets. Filtered Asset Register and Management Summary are report-only exports.

Follow the [Excel workflow guide](docs/excel-workflows.md) for adding new records, previewing and resolving changes, downloading the reconciled workbook, and recovering from Excel. Legacy linked-workbook import/export remains available separately.
